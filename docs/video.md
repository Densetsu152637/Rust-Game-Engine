# File video playback

`engine-video` decodes real local media using configured FFmpeg and ffprobe executables. The engine does not download, bundle, or install them. Supply trusted executable paths with `DecoderTools`; bare defaults resolve `ffmpeg` / `ffprobe` through the host PATH. Missing executables and unsupported media return errors. FFmpeg 7.0.2 was exercised; installed build codecs determine which encoded streams work.

The host can use `VideoPlayer::open(path, tools, Some(audio.control()))` directly, call `poll()` every rendering tick, and upload returned RGBA8 pixels. `pause`, `resume`, `seek(seconds)` and `stop` control playback. Dropping the player closes both decoder subprocesses and the voice. An audio-bearing file requires `AudioControl`; there is no silent success fallback when audio output was omitted. An offline audio engine must be mixed by the caller to advance its source clock.

For authored projects, register a `video` asset and an `engine.VideoPlayer` custom component (version 1) with `asset`, `stream`, optional `captions` caption-track ID, and `autoplay`. Insert `video::RuntimeVideos::new(tools)` in the runtime world before its first tick. This is explicit host opt-in; ordinary runtime loading never launches a decoder. Use `stream:<stream>` in the `MeshMaterial.texture` field of a 3D mesh. The runtime creates a CPU `TextureStreams` stream, uploads due frames before captions advance, and removes playback when the owning entity/component disappears. Stopping or failing an attached player also stops its caption track. Runtime shutdown closes all playback. Inspect/control an attached player through `RuntimeVideos::player` / `player_mut`. Up to eight attached players are admitted; stream names must be unique and unoccupied. MCP `asset_list(kind="video")` and `asset_info` expose catalogue entries; `component_set` authors the component. These authoring operations preserve existing path/size checks and never execute a decoder or infer media metadata. Component changes restart playback. `autoplay: false` leaves the component inactive.

`video::caption_clock(&player)` supplies the same `CaptionClock` used by the authored adapter. Audio-bearing playback uses the mixer's submitted PCM source clock, including pause and underrun holds, and retains the final drained snapshot. It is **not** a hardware presentation timestamp. Silent playback uses a monotonic `Instant` clock, frozen on pause and clamped to duration. Caption clock clones track seek/restart and return `None` after stop/failure. Failed seek startup publishes a terminal error through both `snapshot()` and `poll()`; a standalone player can recover through a later successful seek after restoring a missing file. The authored runtime retains its existing fail-stop tick contract: a playback error shuts down the runtime and its video/caption resources. Call `poll()` regularly to surface decoder errors and present due video frames. Late video frames are dropped to catch up. The decoder extends the final image over any audio-only tail, including seeks into that tail; short audio is padded with silence through the video end. Playback ends when the video queue is exhausted and the audio source has drained (or the silent clock reaches duration).

Decoded video is explicitly resampled to **30 frames/second** using FFmpeg's `fps` filter. Frame timestamps are the later of the preceding seek grid point and the first video grid timestamp, plus the output frame index / 30; these are not original variable-frame-rate timestamps. Seek restarts decoding from the file with an output-side accurate trim. Audio seeks to the requested sample. For seeks after video begins, video starts at the preceding 30fps grid point so the containing frame is available while paused. FFmpeg normalizes nonzero container origins; the decoder retains delayed audio as silence and delays video presentation until its first normalized frame timestamp. Duration uses selected stream end times when available, Matroska segment end minus its start otherwise, and MOV elapsed duration as fallback; audio uses resampling to insert initial silence and is padded to the file duration. Video is fixed-size 8-bit CPU RGBA upload without HDR tone mapping; no hardware decoding, zero-copy import, network streaming, DRM, or audio device latency compensation is claimed.

Accepted demuxers are MOV/MP4 and Matroska/WebM. Playlist demuxers are excluded, nested protocols are restricted to `file`, and MOV external data references remain disabled by the decoder default. These restrictions reduce file indirection; the decoder is **not sandboxed** and untrusted files still enter FFmpeg's native parsers. Hosts remain responsible for trusted executable provisioning and FFmpeg license obligations.

Limits: regular local files, duration at most 24 hours, 4096 pixels per edge and 8,388,608 pixels/frame. Probe output is capped at 64KiB with a ten-second deadline. Each player has three queued RGBA frames, one pending frame and worker staging (plus renderer-owned pixels), and a half-second 48kHz stereo PCM ring with an 8KiB byte staging block and an 8KiB float conversion block. Pipes apply backpressure; cancellation kills/reaps children before joining readers. FFmpeg's internal codec allocations are outside the Rust queue limits (`-max_alloc` bounds a single allocation only). Open/probe and seek are synchronous host operations; avoid placing them on an audio callback.

Run focused integration checks with explicit trusted binaries:

```powershell
$env:ENGINE_VIDEO_FFMPEG = 'C:/tools/ffmpeg.exe'
$env:ENGINE_VIDEO_FFPROBE = 'C:/tools/ffprobe.exe'
cargo test -p engine-video -j1 -- --include-ignored --test-threads=1
cargo test -p engine-project --test video -j1 -- --include-ignored --test-threads=1
```

Real decoder tests generate synthetic lossless media locally; they are ignored by default so a missing external tool cannot be confused with a passed decoder check.

Decoder command behavior is based on the [FFmpeg CLI](https://ffmpeg.org/ffmpeg.html), [format restrictions and MOV defaults](https://ffmpeg.org/ffmpeg-formats.html), and [protocol whitelist](https://ffmpeg.org/ffmpeg-protocols.html).
